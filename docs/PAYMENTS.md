# Платежи и монетизация: исследование и схема

Редакция от 19 ноября 2026. **Реальные платежи не подключены и не подключаются** без отдельного решения владельца,
договора с провайдером и юридической проверки. Тарифы ниже из открытых источников и меняются — запрашивайте
актуальные у банка или провайдера.

## 1. Что продавать (по стратегии)

Обычные объявления бесплатно. Платно: поднятие объявления, VIP на 7 дней, бизнес-профиль PRO, реклама партнёров.
Комиссию со сделок не брать, пока Qoldan не участвует в расчётах между сторонами (сейчас не участвует — это прописано
в оферте и правилах торгов).

## 2. Провайдеры в Казахстане

| Провайдер | Что известно | Что уточнить |
|---|---|---|
| Kaspi Pay | Есть технический регламент платёжной системы с API по HTTP, требованием идемпотентности и методом `refund`. API маркетплейса Kaspi.kz — отдельный продукт для продажи на Kaspi | Подключение собственного сайта к Kaspi Pay, тестовая среда и тарифы — через менеджера Kaspi |
| Halyk ePay | По данным банка, им пользуются более 65% интернет-магазинов РК; с мая 2026 банк объявлял снижение ставок до ~1% за карты и 0,5% за Halyk QR | Актуальный тариф интернет-эквайринга для вашего юрлица |
| Freedom Pay | Провайдер платёжных решений для e-commerce | Тарифы и API |
| ioka, CloudPayments и др. | В открытом поиске актуальных тарифов не нашлось | Запросить у отделов продаж |

Для небольших сумм (поднятие, VIP) практичнее платёжная страница провайдера (redirect): меньше требований к безопасности
сайта, данные карты не попадают на сервер Qoldan.

## 3. Обязательные условия до включения

1. Юрлицо или ИП с расчётным счётом (физлицо без ИП принимать оплату за услуги площадки не должно).
2. Договор с провайдером, онлайн-касса и фискальные чеки (уточнить у бухгалтера).
3. Оферта на платные услуги, правила возврата для платных услуг, цены в тенге с указанием, что входит.
4. Проверка юристом и бухгалтером (налоги, НДС, чеки).

## 4. Техническая схема (готова к реализации, не реализована)

- Таблица `payments`: id, пользователь, услуга (`boost`, `vip_7d`, `pro_month`), сумма в тиынах (целое число),
  валюта KZT, статус (`created` → `pending` → `paid` | `failed` | `refunded`), id у провайдера, ключ идемпотентности,
  время создания и изменения. Статус меняется только вперёд (как триггеры торгов).
- Создание платежа: сервер сам считает сумму по прайсу (клиент не передаёт цену), ключ идемпотентности защищает от
  двойного нажатия.
- Подтверждение **только по серверному уведомлению провайдера** (webhook) с проверкой подписи; возврат пользователя на
  сайт ничего не подтверждает. Повторное уведомление не начисляет услугу второй раз (уникальный id у провайдера).
- Услуга включается в той же транзакции, что и перевод платежа в `paid`.
- Возврат — через метод провайдера и только из статуса `paid`; журнал всех операций не редактируется.
- Тесты: двойное уведомление, поддельная подпись, гонка «оплата и отмена», неверная сумма.

## 5. Решения владельца

Выбор провайдера, форма юрлица, прайс, оферта на платные услуги, договор и касса.
