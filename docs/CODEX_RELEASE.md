# Задание для Codex: выпуск Qoldan на Sites (B4)

Редакция от 26 ноября 2026. Вставить в Codex целиком, в чат проекта Qoldan (рабочая копия `marketplace`).
Выпуск делает только Codex: у Claude нет доступа к публикации Sites и к production-базе.
Каждое действие с production — только после «да» основателя (см. [AGENTS.md](../AGENTS.md)); одно «да» на одно действие.

## Исходное состояние (аудит 25.11.2026 и проверка 26.11.2026)

- `main` проходит `node scripts/check.mjs` целиком (тесты, tsc, линтер 65/65, сборка), сквозной тест `node scripts/e2e-smoke.mjs` на локальном сервере: 17 из 17.
- Живой сайт старее `main`: на нём два подвала и русские строки в английском интерфейсе.
- `HANDOFF.md` до 25.11 писал, что миграции 0022–0026 не применены, но живой `/api/bootstrap` уже отдаёт поля `attributes` и `hasPhone`. Значит, в production есть минимум `0022` и `0024`. Что с `0023`, `0025`, `0026` — неизвестно.
- Вход на production — через ChatGPT-аккаунт (режим `platform`). Менять не нужно.
- В production лежит тестовое объявление с матерным названием. **Не удалять** без отдельного «да» основателя.

## Шаги

1. Подтяни `main` (не ниже коммита после слияния PR с этим файлом), `node scripts/check.mjs` должен пройти.
2. **Резервная копия** production-базы (`scripts/backup.mjs`). Проверь, что файл не пустой, и запиши путь. Копию в репозиторий не добавлять.
3. **Сверка миграций.** Прочитай таблицу применённых миграций в production D1 (только чтение). Выпиши, какие из `0022`–`0026` применены. Не применяй ничего повторно.
4. Покажи основателю список недостающих миграций и дождись «да».
5. Примени недостающие по порядку (`drizzle/0022…` → `0026…`). После каждой — проверка: `/api/health` отвечает `ok`, `/api/bootstrap` отвечает 200.
   Что ломается без них: без `0022`/`0023` падает `/api/bootstrap`; без `0026` не работает добавление в избранное (`app/api/favorites/route.ts`); `0025` нужна только для входа по коду (`QOLDAN_AUTH_MODE=own`).
6. Дождись «да» основателя на публикацию, затем опубликуй Sites из `main`.
7. **Проверка живого сайта** (запиши результат каждого пункта):
   - главная в RU, KK и EN; на английском нет русских строк (кроме названий языков и данных пользователей);
   - на каждой странице один подвал (`/`, `/housing`, `/listing/<id>`, `/request/<id>`, `/legal/*`);
   - несуществующие `/listing/x` и `/request/x` отвечают 404, а не 200;
   - вход через ChatGPT, создание объявления и заявки, отклик, избранное, жилье, карта;
   - `/api/health` = ok; консоль браузера без новых ошибок (одно сообщение CSP Report-Only про `unsafe-eval` ожидаемо, см. [CSP.md](CSP.md));
   - задать `QOLDAN_ADMIN_USER_IDS` или `QOLDAN_ADMIN_EMAILS` в панели Sites после того, как основатель назовёт свои данные (B3), и проверить, что кабинет модерации открывается.
8. **Отчёт:** какие миграции были и какие применены, путь к бэкапу, коммит выпуска, результат каждой проверки из шага 7. Добавь строку в `SAVEPOINT.md`.

## Чего не делать

- Не удалять данные production (тестовое объявление тоже) и не менять фото в хранилище без «да».
- Не включать строгий CSP и не включать `QOLDAN_AUTH_MODE=own` в этом выпуске.
- Не выводить и не коммитить секреты, `.env*`, `.dev.vars*`, резервные копии.
- Не переписывать историю `main`, никакого `--force`.
